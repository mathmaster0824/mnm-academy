# 보안 작업 현황 (PR #11 · #12 · #13) — 범위 고정용 정리

> 이 작업은 앱 점검 중 새로 발견된 **별도 이슈**이며 본래 목표(앱 정상화, 남은 핵심 작업 = 문제저장소)를 대체하지 않는다. 보안 작업은 여기서 **멈춘다**(추가 확장 없음). 운영에는 아무것도 적용하지 않았다.
> 기준: 브랜치 `security/phase1-director-auth` (PR #13), 2026-10-20.

## 2. 만든 보안 변경 (모두 PR 브랜치 안, 미적용)
- `index.html`: `DIRECTOR_AUTH`(기본 `legacy`). `firebase` 모드면 원장 로그인을 Firebase Auth(이메일/비밀번호, 서버 검증)로 처리하고 `meta/settings`(옛 비밀번호 문서)를 읽지 않음. 원장 확인은 원장 전용 경로를 서버에서 읽어 판정(실제 권한은 규칙).
- `security/firestore.rules.phase1.proposed`: 원장 = 비밀번호 로그인 **그리고** 규칙 파일에 적은 원장 UID 일치(`REPLACE_WITH_DIRECTOR_UID` 자리표시자, 게시 전 원장님이 입력). Firestore 문서 허용 목록은 쓰지 않음(옛 규칙 구간에서 변조 가능하므로 폐기). 원장 전용: meta·월말 리포트·피드백·해설사진·집중기록. 학생 세션 기능(숙제 제출·질문·타이머·주말·STAD·답지)은 유지하되 원장 전용 상태값(승인·답변·출석·수동인정)은 보호.
- `security/firestore.rules.phase2.proposed`: 2단계 목표안(학생별 토큰 전제) — 참고용, 1단계 전환과 무관.
- 시험·점검: `tests/rules/*`, `tests/e2e/phase1.e2e.js`, `scripts/rules-lint.js`, CI(`.github/workflows/rules-tests.yml`).
- 문서: `docs/SECURITY_REMEDIATION_PLAN.md`, `SECURITY_PHASE1_CUTOVER.md`(전환 절차), `SECURITY_PHASE1_DECISION_BRIEF.md`(판단 자료).

## 4. 1단계로 해결되지 않는 것 (전환 후에도 남음)
- 학생 간 자료 열람, 학생 4자리 코드 노출에 의한 사칭 로그인.
- 학생 세션의 **문제저장소 직접 읽기·쓰기**(정답키 포함) — 문제저장소 작업과 직접 관련됨(§6).
- 한 문서에 여러 학생 기록이 있는 구조(classRecords·weeklyPlans·fridaySupp).
- 숙제 `reviewCount` 등 앱이 정해 보내는 값 위조, 월말 리포트 앱 기능 잠금(PR #11 상태 유지), 옛 `adminPassword` 값 삭제(별도 승인 필요).

## 6. 문제저장소와의 관계 (범위 고정)
- 문제저장소 컬렉션(`problems`·`problemKeys`·`problemDrafts`·`problemSources`)은 1단계 규칙에서 **현행대로 열어 둔다**(학생 세션이 질문 올리기 때 쓰므로 닫으면 기능이 깨짐). 닫는 것은 문제저장소 작업에서 서버 처리로 옮긴 **뒤**의 별도 작업.
- 문제저장소 작업은 이 보안 PR 과 독립적으로 진행한다. 이 PR 의 전환은 문제저장소 작업을 기다리지 않아도 되고, 문제저장소 작업도 전환을 기다리지 않는다. **보안 범위는 더 넓히지 않는다.**
