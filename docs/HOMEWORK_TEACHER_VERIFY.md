# 학생별 숙제 확인 상태 클릭 수정 (인증 ↔ 미인증)

두 화면에서 같은 기록을 수정합니다. 어느 쪽에서 바꿔도 같은 `submissions` 문서를 쓰므로 양쪽 표시가 같습니다.
1. **반별 페이지** 학생 카드의 **숙제 현황** 날짜 칸(예: `월 ×`, `화 ○`)
2. **학생 상세페이지**의 **최근 숙제 제출 현황** 표의 상태 칸(원장용)

칸을 누르면 그 학생·그 날짜의 숙제 확인 상태가 `인증` ↔ `미인증`으로 바뀝니다. 두 화면은 같은 저장 함수(`toggleHomeworkVerify`)와 같은 저장 중/성공/실패 상태를 공유합니다. (학생 상세에서 같은 날짜에 두 반 숙제가 겹치면 표는 '더 나쁜 상태' 쪽 반의 기록을 보여 주므로, 그 반의 기록을 수정합니다.)

## 저장 방식 (기존 구조 그대로)
- 저장 위치: 기존과 같은 `submissions/<학생ID 또는 반 슬롯ID>_<날짜>` 문서 **1건만** 씁니다(`set(..., {merge:true})`). 다른 학생·날짜·반 문서는 건드리지 않습니다.
- 기기로 낸 제출이 **없는** 날 인증: 새 문서를 만들고 `status:'확인'`, `verifyMethod:'teacher-direct'`, `verifiedAt`, `studentId/classId/date`를 기록합니다. 사진·제출시각은 없습니다. 화면에는 `○ 직접`, 라벨은 "선생님 직접 확인"이라 기기 제출("제출 완료")과 구분됩니다.
- 기기로 낸 제출이 **있는** 날: 사진·제출시각은 그대로 두고 `status`만 바꿉니다(인증 → `확인`, 해제 → 기존 `대기`=검토대기). `verifyMethod`는 붙이지 않으므로 기기 제출로 남습니다.
- 직접 확인을 해제하면 문서를 지우지 않고 `status:'미인증'`으로 바꿉니다(학생이 그 사이 제출했을 수 있는 기록을 지우지 않기 위해). 앱은 `미인증`을 "기록 없음(미제출)"과 같게 집계합니다.
- 새 이력 컬렉션·필드 체계는 만들지 않았습니다(`verifyMethod`, `verifiedAt` 두 필드만 추가).

## 화면 안내
- 저장 중: 칸에 `… 저장 중`, 칸 잠김. 성공: `✓` + "인증 저장됨/미인증 저장됨"(2.5초). 실패: `✖ 저장 실패` + "저장 실패 · 다시 눌러주세요"(6초), 화면·서버 데이터는 이전 그대로.
- 화면 데이터는 **저장 성공 뒤에만** 바뀝니다.

## 막아 둔 경우
- 학생 세션: 칸이 클릭 칸으로 그려지지 않고, 호출해도 저장하지 않습니다.
- 2026-09-07 이전(리스타트 이전) 날짜, 아직 오지 않은 날짜, 3회 검사가 끝난 최종 불합격 기록, 다른 반 기록과 겹치는 문서는 저장하지 않고 이유를 표시합니다.
